# BRD-001. Мини-игра «Скретч-карта студента»: бизнес-требования

| Поле | Значение |
|---|---|
| Идентификатор | BRD-001 |
| Версия | 2.0 |
| Статус | Черновик для согласования |
| Связанные документы | RFC-0001 (техническое решение), README (запуск и встраивание) |
| Целевая аудитория продукта | Студенты, клиенты банка, сегмент «молодёжь» |

## 1. Назначение документа

Документ фиксирует бизнес-цели, область действия, требования, правила и критерии успеха мини-игры, которая встраивается в мобильное приложение банка и другие продукты экосистемы. Технические решения вынесены в RFC-0001. Каждое бизнес-требование прослеживается до технического раздела (см. §13).

## 2. Контекст и проблема

1. Студенческая аудитория открывает приложение ради разовых операций и редко заходит в раздел партнёрских предложений.
2. Скидки партнёров в каталоге воспринимаются как реклама и обнаруживаются случайно.
3. Банку нужен лёгкий повод для повторного входа без дорогих кампаний и без сложных условий для клиента.

**Решение.** Игровой сеанс до одной минуты, в котором:
- действие пользователя одно: стереть защитный слой карты;
- награда гарантирована в каждой игре, ценность награды различается;
- награда ведёт к партнёру банка: пользователь копирует код и переходит на площадку партнёра;
- игра поставляется как независимый встраиваемый модуль, который подключается к любому продукту банка без доработки.

## 3. Цели и метрики успеха

Целевые значения являются гипотезами и уточняются по итогам пилота.

| ID | Метрика | Определение | Цель |
|---|---|---|---|
| M-01 | Доля завершённых игр | Игры с раскрытым призом / начатые игры | ≥ 85% |
| M-02 | Длительность сеанса | От нажатия «Играть» до экрана промокода, p95 | ≤ 30 с |
| M-03 | Скорость стирания | От первого касания до раскрытия приза, медиана | ≤ 3 с |
| M-04 | Доля копирования | Копирования кода / раскрытые призы | ≥ 60% |
| M-05 | Переход к партнёру | Переходы / раскрытые призы | ≥ 35% |
| M-06 | Возврат | Пользователи с ≥ 2 играми за 14 дней / все игравшие | ≥ 30% |
| M-07 | Погашение | Использованные коды / выданные коды (по данным партнёров) | ≥ 12% |
| M-08 | Стоимость подключения | Время интеграции модуля в новый продукт | ≤ 1 рабочий день |

## 4. Область действия

**В области:**
- механика «скретч-карта» с четырьмя уровнями призов;
- каталог партнёров и предложений, выдача и учёт промокодов;
- встраиваемый модуль с настройкой темы, аналитики и перехода к партнёру;
- ограничения и антифрод;
- аналитика воронки.

**Вне области (этап 1):**
- денежные призы и участие несовершеннолетних;
- розыгрыши с неопределённым для пользователя исходом;
- интеграция с платёжными операциями банка;
- кабинет партнёра и экран «Мои коды» (этап 2).

## 6. Пользователи и сценарии

**Персона.** Студент 18–23 лет, пользуется телефоном, ценит скорость, откликается на скидки на кофе, книги, транспорт и обучение.

### 6.1. Основной сценарий

| Шаг | Действие пользователя | Реакция системы |
|---|---|---|
| 1 | Открывает экран игры, нажимает «Играть» | Создаётся игра, открывается карта; на карте подсказка-жест |
| 2 | Проводит пальцем по карте (2–3 росчерка) | Слой стирается, шкала прогресса растёт, свечение под слоем усиливается |
| 3 | Достигает порога стирания | Слой исчезает, показывается приз, короткая вибрация |
| 4 | Нажимает «Забрать промокод» | Открывается экран промокода |
| 5 | Нажимает «Скопировать код» | Код в буфере обмена, подтверждение на 2 с |
| 6 | Нажимает «Перейти к партнёру» | Открывается площадка партнёра с метками и кодом |

Шаг 4 сохраняет контроль за пользователем: приз можно рассмотреть, переход не происходит сам. Основное игровое действие по-прежнему одно (шаг 2).

### 6.2. Пользовательские истории и критерии приёмки

**US-01. Запуск игры.**
```gherkin
Given пользователь авторизован и не играл сегодня
When он нажимает «Играть»
Then создаётся игра и открывается экран карты в течение 1 с (p95)
And на карте показана подсказка-жест, пока пользователь не коснулся карты
```

**US-02. Быстрое и плавное стирание.**
```gherkin
Given открыта карта
When пользователь проводит пальцем по карте
Then стирание следует за пальцем непрерывной линией без разрывов
And шкала прогресса отражает долю пути до порога
And при стирании 30% площади защитный слой исчезает и показывается приз
```

**US-03. Гарантированная награда.**
```gherkin
Given игра создана
When достигнут порог стирания либо нажата «Открыть без стирания»
Then пользователь видит приз с названием партнёра и условием
And в любом состоянии пула кодов выдаётся код того же или ближайшего меньшего уровня
```

**US-04. Копирование кода.**
```gherkin
Given открыт экран промокода
When пользователь нажимает «Скопировать код»
Then код оказывается в буфере обмена, кнопка показывает «Скопировано» 2 с
And при недоступности буфера показана инструкция ручного копирования
```

**US-05. Переход к партнёру.**
```gherkin
Given открыт экран промокода
When пользователь нажимает «Перейти к партнёру»
Then продукт-хост получает событие перехода и может обработать его сам
And без обработки хостом ссылка открывается в новой вкладке
And в ссылке переданы UTM-метки и код
```

**US-06. Дневной лимит.**
```gherkin
Given пользователь уже сыграл в текущие сутки (МСК)
When он нажимает «Играть»
Then показано сообщение, что следующая карта будет завтра
```
На этапе 2 состояние показывается до нажатия и содержит список полученных кодов.

**US-07. Сбой сети.**
```gherkin
Given связь с сервером прервана при запуске или раскрытии
When запрос не выполнен
Then показано сообщение с действием «повторить»
And повтор не создаёт вторую игру и не выдаёт второй код
```

**US-08. Встраивание.**
```gherkin
Given разработчик продукта-хоста подключает модуль
When он добавляет элемент на страницу и передаёт реализацию API
Then игра работает без конфликтов со стилями страницы
And хост получает события аналитики и может заменить переход к партнёру
```

## 7. Бизнес-правила

| ID | Правило |
|---|---|
| BR-01 | Одна карта на пользователя в сутки по московскому времени. |
| BR-02 | Приз определяется на сервере при создании игры и не зависит от действий пользователя при стирании. |
| BR-03 | Награда гарантирована: каждая завершённая игра приводит к выдаче ровно одного кода. |
| BR-04 | Один код выдаётся не более одного раза и привязан к игре. |
| BR-05 | Срок действия кода — 14 дней с момента выдачи, если партнёр не задал меньший. |
| BR-06 | При исчерпании пула выбранного уровня выдаётся код ближайшего меньшего уровня; при пустом пуле — резервный код банка. |
| BR-07 | Веса уровней и список предложений меняются конфигурацией без выпуска приложения. |
| BR-08 | Экран сопровождается рекламной пометкой и ссылкой на правила акции. |
| BR-09 | Модуль не хранит и не передаёт персональные данные; пользователь идентифицируется обезличенным идентификатором хоста. |
| BR-10 | Решение о способе перехода к партнёру (внешний браузер, внутренний экран, deep link) принадлежит продукту-хосту. |

### 7.1. Экономика призов

Номинал рассчитан для среднего чека 500 ₽ и показывает скидку, которую предоставляет партнёр при использовании кода.

| Уровень | Вероятность | Типовое предложение | Номинал, ₽ | Игр из 1000 |
|---|---|---|---|---|
| Обычный | 55% | Скидка 5% | 25 | 550 |
| Необычный | 28% | Скидка 10% | 50 | 280 |
| Редкий | 13% | Скидка 20% либо напиток | 100 | 130 |
| Эпический | 4% | Скидка 30% либо подарок до 500 ₽ | 150 | 40 |

Ожидаемый номинал одного кода: 0,55·25 + 0,28·50 + 0,13·100 + 0,04·150 = **46,75 ₽**; на 1000 игр — 46 750 ₽ номинала. При погашении 12% (M-07) фактические расходы партнёров составляют около 5 610 ₽ на 1000 игр, поскольку скидка реализуется только при покупке.

## 8. Требования к встраиванию

| ID | Требование |
|---|---|
| IR-01 | Модуль подключается одним файлом и одним HTML-элементом. |
| IR-02 | Стили модуля и страницы хоста не влияют друг на друга. |
| IR-03 | Хост передаёт реализацию серверного API; модуль не содержит секретов и адресов окружений. |
| IR-04 | Хост получает все события воронки и пересылает их в сквозную аналитику. |
| IR-05 | Хост может заменить переход к партнёру собственным. |
| IR-06 | Тема (цвета) настраивается без правки кода модуля. |
| IR-07 | Модуль работает в мобильных браузерах, WebView банковского приложения и настольных браузерах. |
| IR-08 | Изменения контракта выпускаются с семантическим версионированием. |

## 9. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-B1 | Работа на экранах от 360 px. |
| NFR-B2 | Доступность: управление с клавиатуры, альтернатива жесту («Открыть без стирания»), озвучивание прогресса, учёт «уменьшенного движения». |
| NFR-B3 | Отклик при стирании без заметных задержек на смартфонах среднего класса. |
| NFR-B4 | Пиковая нагрузка акции: до 100 запросов в секунду без деградации. |
| NFR-B5 | Размер модуля в сжатом виде не более 150 КБ. |

## 10. Допущения и ограничения

1. Партнёры предоставляют пулы кодов заранее либо API генерации.
2. Хост поддерживает веб-элементы и передаёт токен сессии.
3. Правила акции и рекламная маркировка согласуются юристами до запуска. Партнёры в прототипе вымышленные.
4. Палитра заимствует цвета бренда и сверяется с брендбуком. Официальный логотип не используется.
5. Серверная часть описана в RFC-0001 и в прототипе заменена локальной имитацией.
