# RFC-0001. Архитектура сервиса и встраиваемого модуля «Скретч-карта студента»

| Поле | Значение |
|---|---|
| Идентификатор | RFC-0001 |
| Версия | 2.0 |
| Статус | Proposed |
| Основание | BRD-001 |
| Терминология | MUST, SHOULD, MAY интерпретируются по RFC 2119 |

## 1. Резюме

Решение состоит из двух частей:
1. **Встраиваемый клиентский модуль** — веб-элемент `<agro-scratch-game>` на React и TypeScript с Shadow DOM, поставляемый одним ES-модулем. Он отвечает за отрисовку, жест стирания и события. Все внешние зависимости (API, аналитика, переход к партнёру) передаются хостом.
2. **Сервис игры** на Node.js (Fastify) с PostgreSQL и Redis. Он определяет приз, выдаёт код и ведёт учёт.

## 2. Статус реализации

| Компонент | Состояние |
|---|---|
| Веб-элемент, экраны, `ScratchCard`, шкала прогресса, подсказка-жест | Реализовано в прототипе |
| Интерфейс `GameApi`, имитация `mockGameApi` | Реализовано |
| HTTP-клиент `createHttpGameApi` (токен, идемпотентность, повтор, ошибки) | Реализовано, покрыт модульными тестами |
| Модульные тесты конфигурации призов, выбора уровня, имитации и HTTP-клиента | Реализовано |
| Сервис игры, БД, Redis, антифрод на сервере | Описано в RFC, не реализовано |
| Статистические, интеграционные, E2E, нагрузочные тесты | Запланировано (§15) |

Прототип не собирался и не запускался автоматически при подготовке документа; перед показом MUST быть выполнены `npm test`, `npm run build`, `npm run build:element`.

## 3. Цели и не-цели

**Цели:** гарантированная выдача кода; невозможность подмены исхода клиентом; идемпотентность; быстрый и плавный жест; встраивание без конфликтов; конфигурируемая экономика; наблюдаемость.

**Не-цели:** собственная система авторизации, хранение персональных данных, кабинеты партнёров, локализация (этап 2).

## 4. Принятые решения (ADR)

| ID | Решение | Альтернативы | Обоснование |
|---|---|---|---|
| ADR-1 | React 18, TypeScript, Vite | SvelteKit, Next.js | Распространённый стек, строгая типизация контрактов |
| ADR-2 | Framer Motion для переходов; CSS с переменными вместо Tailwind | Tailwind | Небольшой набор экранов; токены темы в одном файле переопределяются снаружи |
| ADR-3 | Скретч-слой на Canvas 2D | CSS-маски, WebGL | Достаточная производительность, нет зависимостей |
| ADR-4 | Исход определяется на сервере при создании игры | Клиентский ГСЧ | Исключает подмену и повторные попытки |
| ADR-5 | Fastify, PostgreSQL | NestJS, NoSQL | Транзакционная выдача кодов, `SELECT … FOR UPDATE SKIP LOCKED` |
| ADR-6 | Клиент работает через интерфейс `GameApi` | Прямые `fetch` | Подмена реализации в демо, тестах и хостах |
| ADR-7 | Поставка в виде веб-элемента с Shadow DOM | Библиотека React-компонентов, iframe | Не зависит от фреймворка хоста, изоляция стилей, меньше накладных расходов, чем iframe |
| ADR-8 | Учёт покрытия по сетке клеток | `getImageData` по холсту | Нет копирования пикселей на каждом замере, порог проверяется в событии жеста |
| ADR-9 | Переход к партнёру — отменяемое событие хоста | Жёсткий `window.open` | Хост управляет WebView, внешним браузером, deep link |
| ADR-10 | Раскрытие приза по кнопке «Забрать промокод» | Автопереход по таймеру | Пользователь успевает рассмотреть приз; нет неожиданной смены экрана |

## 6. Клиентский модуль

### 6.1. Автомат экранов

| Состояние | Событие | Следующее состояние |
|---|---|---|
| `launch` | `startGame` успешен | `play` |
| `launch` | `startGame` завершился ошибкой | `launch` + сообщение (§9) |
| `play` | порог стирания либо кнопка «Открыть без стирания» | `play`, ожидание `reveal` |
| `play` | `reveal` вернул приз | `play`, приз показан, кнопка «Забрать промокод» |
| `play` | `reveal` завершился ошибкой | `play` + сообщение; повторить можно кнопкой «Открыть без стирания» |
| `play` | нажата «Забрать промокод» | `reward` |
| `reward` | «Скопировать код» | `reward`, статус копирования 2 с |
| `reward` | «Перейти к партнёру» | `reward`, событие `agro-open-partner` |
| `reward` | «Сыграть ещё раз (демо)» | `launch` |

Кнопка «Сыграть ещё раз (демо)» MUST быть скрыта в продуктовой сборке: действует дневной лимит BR-01.

### 6.2. Компонент `ScratchCard`

| Параметр | Значение | Назначение |
|---|---|---|
| Логический размер | 340 × 210 | Холст масштабируется по ширине контейнера |
| Радиус кисти | 40 | Достаточно 2–3 росчерков |
| Порог открытия | 30% площади | Настраивается константой `THRESHOLD` |
| Сетка покрытия | 34 × 21 клеток (шаг 10) | Учёт без чтения пикселей |
| Ограничение `devicePixelRatio` | 2 | Баланс чёткости и нагрузки |
| Вибрация | 15 мс при пороге | `navigator.vibrate`, если поддерживается |

Алгоритм:
1. Слой рисуется градиентом с узором борозд; режим стирания `destination-out` и параметры линии задаются один раз при инициализации.
2. Жест рисуется непрерывной линией со скруглёнными концами между точками касания; используются промежуточные точки `getCoalescedEvents`, если браузер их предоставляет.
3. Для каждой точки отрезка отмечаются клетки сетки внутри круга радиуса `0,85 × радиус кисти` (прогресс не завышается).
4. Прогресс = покрытые клетки / все клетки / порог, ограничен 1. Событие `onProgress` вызывается при изменении целого процента, `onThreshold` — один раз.
5. Прямоугольник холста измеряется один раз на жест, а не на каждое движение.
6. Клиент MUST NOT вычислять приз; приз показывается только после ответа `reveal`.

Под слоем отображается светлое поле с узором и свечение, яркость и размер которого зависят от прогресса; текстовых заглушек нет. После порога слой исчезает за 0,2 с, приз появляется с короткой анимацией.

### 6.3. Подсказка и обратная связь

1. Пока пользователь не коснулся карты, поверх неё плавно движется точка-подсказка.
2. Шкала прогресса под картой отражает долю пути до порога.
3. Заголовок и подпись меняются после раскрытия приза.

### 6.4. Доступность

| Требование | Реализация |
|---|---|
| Альтернатива жесту | Кнопка «Открыть без стирания» |
| Озвучивание | `role="progressbar"` для шкалы, `role="status"` для подписи, холст скрыт (`aria-hidden`) |
| Фокус | Фокус переходит на «Забрать промокод»; видимая обводка фокуса |
| Движение | `prefers-reduced-motion` отключает подсказку, свечение, анимацию приза и переходы экранов |
| Контраст | Токены темы проверяются на соответствие WCAG AA |

### 6.5. Дизайн-токены

Определены на `:host`: `--g900`, `--g700`, `--g500` (зелёные), `--lime` (акцент), `--bg`, `--ink`, `--muted`, `--line`. Хост MAY переопределить их стилями на элементе: `agro-scratch-game { --g700: #…; }`. Значения MUST быть сверены с брендбуком.

## 7. Контракт встраивания

| Элемент | Тип | Описание |
|---|---|---|
| `api` | свойство, `GameApi` | MUST быть задано хостом до или после подключения элемента |
| `agro-event` | `CustomEvent<GameEvent>` | События воронки (§12); `bubbles`, `composed` |
| `agro-open-partner` | `CustomEvent<Prize>`, cancelable | `preventDefault()` передаёт переход хосту; иначе модуль открывает `deepLink` в новой вкладке с `noopener,noreferrer` |
| CSS-переменные | см. §6.5 | Настройка темы |

Интерфейсы:
```ts
interface GameApi {
  startGame(): Promise<{ gameId: string }>;
  reveal(gameId: string): Promise<Prize>;
}
interface GameEvent { name: GameEventName; ts: number; payload: Record<string, unknown>; }
class GameError extends Error { code: GameErrorCode; nextAt?: string }
```

Пример подключения приведён в README. Требования к хосту: CSP разрешает загрузку модуля; шрифт Manrope подключается хостом, иначе используется системный; хост предоставляет токен через `getToken`.

## 8. Контракт серверного API

Базовый путь `/v1`. Аутентификация: `Authorization: Bearer <JWT>`; идентификатор клиента `sub` обезличен.

### 8.1. `POST /v1/games`

Создаёт игру. Заголовок `Idempotency-Key` MUST быть передан.

| Код | Ситуация | Тело |
|---|---|---|
| 201 | Игра создана | `{ "gameId": "uuid" }` |
| 200 | Повтор с тем же ключом | Исходный ответ |
| 409 | Лимит суток исчерпан | `{ "code": "DAILY_LIMIT", "nextAt": "ISO-8601" }` |
| 429 | Превышен rate limit | `{ "code": "RATE_LIMIT" }` |

### 8.2. `POST /v1/games/{gameId}/reveal`

Тело: `{ "elapsedMs": number }`. Сервер MUST отклонять запрос, если с момента создания игры прошло менее 400 мс по серверным часам (`TOO_FAST`, 422). Порог выбран ниже минимального естественного времени стирания, чтобы не блокировать быстрых пользователей.

| Код | Ситуация | Тело |
|---|---|---|
| 200 | Приз выдан (идемпотентно) | `Prize` |
| 404 | Игра не найдена или чужая | `{ "code": "GAME_NOT_FOUND" }` |
| 410 | Игра просрочена (> 15 мин) | `{ "code": "GAME_EXPIRED" }` |
| 422 | Слишком быстрый запрос | `{ "code": "TOO_FAST" }` |

`Prize`: `{ tier, partner{id,name,category,codePrefix,url}, title, code, expiresAt, deepLink }`.

### 8.3. Идемпотентность и повторы

1. `createHttpGameApi` генерирует один `Idempotency-Key` на запуск игры и при сетевой ошибке повторяет запрос один раз с тем же ключом.
2. Повторный `reveal` возвращает тот же `Prize` без побочных эффектов.
3. Таймаут запроса по умолчанию — 8 с.

### 8.4. `GET /v1/codes` (этап 2)

Возвращает коды пользователя, пагинация курсором.

## 9. Ошибки

| Код | Источник | Сообщение пользователю |
|---|---|---|
| `DAILY_LIMIT` | 409 | Сегодняшняя карта уже сыграна. Следующая будет завтра. |
| `RATE_LIMIT` | 429 | Слишком много попыток. Подождите минуту. |
| `NETWORK` | сбой сети, таймаут | Нет соединения. Проверьте сеть и попробуйте ещё раз. |
| `GAME_EXPIRED` | 410 | Карта устарела. Начните новую игру. |
| `GAME_NOT_FOUND`, `TOO_FAST`, `UNKNOWN` | 404, 422, прочее | Что-то пошло не так. Попробуйте ещё раз. |

Тексты не содержат технических подробностей и подсказывают действие.

## 10. Модель данных

| Таблица | Поля | Ограничения |
|---|---|---|
| `partners` | `id`, `name`, `category`, `base_url`, `active` | PK `id` |
| `offers` | `id`, `partner_id`, `tier`, `title`, `valid_days`, `active` | FK `partner_id` |
| `tier_config` | `tier`, `weight`, `version`, `active_from` | `SUM(weight)` = 1 на версию |
| `promo_codes` | `id`, `offer_id`, `code`, `status`, `game_id`, `issued_at` | UNIQUE `code`; `status` ∈ {AVAILABLE, ISSUED, REDEEMED, EXPIRED} |
| `games` | `id`, `user_id`, `day_msk`, `tier`, `code_id`, `state`, `created_at`, `revealed_at` | UNIQUE (`user_id`, `day_msk`) |
| `idempotency_keys` | `key`, `user_id`, `response`, `created_at` | UNIQUE (`user_id`, `key`) |
| `events` | `id`, `name`, `user_id`, `game_id`, `payload`, `ts` | Индекс (`name`, `ts`) |

`user_id` — обезличенный идентификатор хоста. Ограничение UNIQUE (`user_id`, `day_msk`) обеспечивает BR-01 на уровне БД.

## 11. Алгоритмы сервера

### 11.1. Выбор приза

1. Загрузить активную версию `tier_config`.
2. Получить `r ∈ [0, 1)` из CSPRNG на сервере.
3. Выбрать уровень: первый, для которого `r < Σ weight`.
4. Выбрать предложение уровня равновероятно среди активных.
5. В одной транзакции зарезервировать код: `SELECT … WHERE offer_id = ? AND status = 'AVAILABLE' FOR UPDATE SKIP LOCKED LIMIT 1`, затем `status = 'ISSUED'`, `game_id = ?`.
6. Если кода нет, понизить уровень на шаг и повторить с п. 4; если уровни исчерпаны, выдать резервный код банка (BR-06) и создать алерт.

Инвариант: игра в состоянии `REVEALED` всегда имеет `code_id`.

### 11.2. Жизненный цикл игры

`CREATED → REVEALED → CLOSED`; `CREATED → EXPIRED` по таймауту 15 минут. Код игры в `EXPIRED` возвращается в пул фоновым заданием.

## 12. Аналитика

| Событие | Источник | Поля |
|---|---|---|
| `game_open` | Клиент | — |
| `game_start` | Клиент | `gameId` |
| `scratch_threshold` | Клиент | `gameId` |
| `prize_reveal` | Клиент | `gameId`, `tier`, `partner` |
| `code_copy` | Клиент | `tier`, `partner` |
| `partner_click` | Клиент | `tier`, `partner` |

Клиент отправляет события хосту событием `agro-event` (поля `name`, `ts`, `payload`). Воронка: `game_open → game_start → scratch_threshold → prize_reveal → code_copy → partner_click`.

| Метрика BRD | Вычисление |
|---|---|
| M-01 | `prize_reveal` / `game_start` |
| M-02 | `prize_reveal.ts` − `game_start.ts` (p95) плюс переход на экран промокода |
| M-03 | `scratch_threshold.ts` − `game_start.ts` (медиана, приближённо) |
| M-04 | `code_copy` / `prize_reveal` |
| M-05 | `partner_click` / `prize_reveal` |
| M-07 | Отчёты партнёров, сопоставление по коду |

Для точного M-03 рекомендуется добавить в `payload` время первого касания (запланировано).

## 13. Безопасность и антифрод

| Угроза | Контроль |
|---|---|
| Подмена исхода на клиенте | ADR-4: исход хранится на сервере |
| Перебор кодов | Формат кода с энтропией не менее 36 бит; коды доступны только владельцу игры |
| Множественные игры | UNIQUE (`user_id`, `day_msk`), rate limit по пользователю и IP |
| Скрипты и боты | Минимальное время до `reveal` (400 мс), анализ аномалий по `events` |
| Повтор запросов | `Idempotency-Key`, срок хранения 24 часа |
| Утечка данных | Нет персональных данных; журналы без кодов в открытом виде |
| XSS и внедрение | Строгая CSP, отсутствие `dangerouslySetInnerHTML`, `noopener,noreferrer` для внешних ссылок |
| Влияние хоста на модуль | Shadow DOM изолирует стили; хост не получает доступ к приватному состоянию React |

Формат кода: `<ПРЕФИКС>-<уровень><3 символа>-<4 символа>` из 32-символьного алфавита без `O`, `0`, `I`, `1`. Обработка данных MUST соответствовать 152-ФЗ; основания подтверждает юридический отдел.

### 15.1. Ключевые тест-кейсы

| ID | Предусловие | Действие | Ожидание |
|---|---|---|---|
| TC-01 | Новый пользователь | Создать игру, раскрыть приз | Код выдан, `state = REVEALED` |
| TC-02 | Игра сыграна сегодня | Повторный `POST /games` | 409 `DAILY_LIMIT`, пользователю показано сообщение |
| TC-03 | Повтор `reveal` | Два запроса подряд | Один и тот же код |
| TC-04 | Пул уровня пуст | Создать игру | Код уровня ниже, приз выдан |
| TC-05 | Параллельность | 500 игр на пуле из 500 кодов | Нет дублей, нет потерянных кодов |
| TC-06 | `reveal` через 100 мс | Отправить запрос | 422 `TOO_FAST` |
| TC-07 | Буфер обмена недоступен | «Скопировать код» | Показана инструкция ручного копирования |
| TC-08 | Сеть пропала на `reveal` | Повторить запрос | Приз выдан один раз |
| TC-09 | Быстрый жест | Два быстрых росчерка через карту | Линия без разрывов, порог достигнут, приз показан |
| TC-10 | Прогресс | Стереть 15% площади | Шкала показывает около 50% |
| TC-11 | Хост отменяет переход | `preventDefault()` на `agro-open-partner` | Новая вкладка не открывается |
| TC-12 | Стили хоста агрессивны | Глобальные стили на `button`, `h1` | Вид модуля не меняется |
| TC-13 | Уменьшенное движение | Включить `prefers-reduced-motion` | Подсказка и анимации отключены |
| TC-14 | Нет жеста | Только клавиатура | Приз открывается кнопкой, фокус на «Забрать промокод» |

## 17. Развёртывание и эксплуатация

1. Модуль раздаётся как статический файл через CDN; сервис — контейнер, не менее двух реплик.
2. Веса и предложения — таблицы БД с версионированием, кэш в Redis на 60 с.
3. Алерты: остаток пула < 10% по предложению; доля резервных кодов > 1%; p95 выше порогов NFR-1, NFR-2.
4. Откат: отключение флага функции скрывает вход в игру; выданные коды остаются действительными.
